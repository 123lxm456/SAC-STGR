# M2 独立候选：技术依据、运行与验收边界

研究方案正本为 `chapters/03_methods_experiments_brief.md`。P5 真实结果见 `reports/p5_analysis_20261128/report.pdf`：M1 相对 B0 的跨密度碰撞事件率更高，A-B 去固定近期偏置的跨密度五项均值均优于 M1，且结果受种子与场景影响。由此提出 M2：保留原九 token 空间层、逐位置时间层和末步自车条件读出，仅把时间近期偏置系数由固定 0.2 改为单个有界可学习系数，零初始化，β=0.2 tanh(θ)。它只多 1 个参数，初始与 A-B 在数学上相同；梯度可使其向任一方向变化。β 不作为新物理冲突先验，不能从注意力权重推出因果解释。

**关键限制：**当前 `Env.reward_compute` 的效率和碰撞奖励与精简稿 3.3 不符。本候选运行仍复用历史 P5 奖励、P4 H=10 标签、风险优化器和训练场景，因此只能测试“时间偏置可学习”这一局部改动，不能声称完整执行精简稿奖励，也不能据单种子结果宣称安全或效率改善。若要执行精简稿奖励，必须先实现动作后真实位移和车辆对物理碰撞的时序归属，再对全部学习组统一重训。切勿只改 M2。历史 P5 协议和结果必须保持冻结。

在原 Linux/RTX 4090 服务器、原项目根目录，确认 `plan/p5/runs/20261123T094822803672Z/plan.json` 中训练场景文件仍存在，并使用**新的种子 41**执行：

```bash
python -B scripts/run_candidate.py --seed 41 --source-plan plan/p5/runs/20261123T094822803672Z/plan.json
```

入口创建 `plan/p5/candidate-runs/<UTC>-m2-41/`，将完整独立命令写入 `command.json`，训练计划写入 `plan.json`，标准输出写入 `train.log`，退出码写入 `exitcode`，模型及训练摘要位于 `online/m2/41/`。创建目录使用排他模式，绝不覆盖旧目录；运行时会打印确切绝对结果路径。训练预算为 100,000 个**决策步**，不是仿真步；`episode_decisions=1000`、`update_every=50`、每次触发最多 3 次风险更新沿用旧 P5。每次运行新建目录，故重复执行也不覆盖。该命令仅训练，不自动评估，不构成论文主矩阵。服务器若缺少原冻结场景或目标 CUDA 环境不匹配，应停止并修复来源，而非指向不同场景替代。
