默认使用此前未用过的 train 种子 101、102、103，B0/M1 各采集三次、每次 2,000 个决策。复用原训练数据与被冻结的验证/测试数据。预算预先固定，不以凑够正例数提前停止；正例不足时仍返回 2。

入口复用 `collect_p4.py` 和 `audit_datasets()`，检查继承的工程代码、锁定环境及冻结检查点。新数据只写 `plan/p4/runs/<UTC时间>-train-extension/`；原始 JSONL 必须仍保存在服务器。开始/结束核对验证测试数据 SHA-256，合并审计要求验证/测试结果与原审计一致；新 JSONL 必须已被 Git 忽略。原数据和模型不修改。

退出码 0 表示合并数据达到现有 P4 支持门槛、审计通过，待回传核验；2 表示仍缺训练自然事件；1 表示执行或完整性检查失败。回传整个新目录中的摘要、计划、环境、源码清单、两份 audit/SVG 和日志。大 JSONL 继续保留在服务器，不能强行加入 Git。

若首轮扩展仍不足，保留成功扩展，并指定其目录继续：

```bash
python -B scripts/extend_p4_train.py --previous-extension plan/p4/runs/实际的扩展目录
```

此时自动接续未用过的种子（例如 104、105、106），保留此前训练数据；拒绝重复种子、不同场景/协议/检查点的混合。种子范围仍限制在 100–149。

`--plan-only` 仅打印计划，可在本机检查种子与冻结目录，不访问 GPU或实际采集。新增规划回归六项，覆盖新种子、冻结路径、继承已完成扩展、重复种子、检查点混合、原验收门槛及非法预算；原模型/标签/审计实现未改，沿用已通过的目标工程证据。
