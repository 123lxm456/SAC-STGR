## 已锁定协议

机器协议为 [protocol.json](protocol.json)，源码常量为 `algos/horizon_risk.py::PROTOCOL`；验收入口要求二者完全一致。版本 `p4-h10-v1`。

| 项目 | 定义 |
|---|---|
| 历史 | T=10；复用 P1 左侧补零及显式布尔有效步掩码 |
| 预测窗 | H=10 个 SUMO 仿真步；当前步长为 1 秒，因此为未来 10 秒，与十次车辆决策区别对待 |
| 时间区间 | 在仿真步 t 观测、选动作，执行推进后观察 t+1；标签区间为 `(t,t+10]` |
| 正例 | 该被评分物理车辆在区间内出现在 SUMO 真实碰撞 ID 中，全路网范围，优先于同一步到达 |
| 负例 | 完整观察未来 10 步且未碰撞，或此前 SUMO 确认到达目的地 |
| 删失 | 未满 H 时异常消失、重置、采集预算结束或中断；标签为 null，排除训练与二元评价 |
| 控制区出口 | 不直接视作安全终局；即便不再有 RL 决策，仍逐仿真步跟踪未来结局 |
| 动作 | 与 SUMO 接收的有界加速度命令一致；不是实测车辆加速度，也不构成独立动作因果效应 |
| 概率解释 | 后续实际动作由指定行为策略决定；未校准的网络输出仍为风险分数 |
| 校准 | 仅自然比例 validation 拟合带 L2 正则的 Platt 映射；test 只应用，不拟合、不选阈值 |
| 阈值和分箱 | 固定阈值 0.5，10 个等宽校准箱；空箱显式保留计数 0 |

H=10 是本阶段明确的初始研究协议选择，不是既有实验已证明的最优预测窗。若改 H、碰撞范围或划分，需要新协议版本与新数据，禁止混用旧样本。

## 实现与兼容

`HorizonRiskBuffer` 继承 P1 缓冲区，复用历史切分、补零、双池平衡抽样及 B0/M1 的同一 BCE 优化器。每次评分先暂存窗口；环境实际发送命令后确认动作，再在 SUMO 步进成功、原始事件返回后提交为已执行决策。原始事件日志同时保存已发送命令，与窗口末步动作交叉核验；消失而被环境跳过的车辆不会被误计为执行了动作。未能确认步进完成的暂存窗口不生成标签。旧终局 `update_data()` 在 P4 缓冲区中不再生成训练样本。

`Env.step_once()` 在旧路口碰撞过滤之前转交原始物理事件，空控制步同样调用。因此碰撞范围不会被原控制区逻辑悄悄缩小。语义片段变化仅重建输入历史，不丢弃此前已执行窗口的未来结局。

现有入口默认仍是 `--risk_supervision legacy`，P0–P3 的 CLI、98 维状态、连续动作、奖励公式和网络权重布局均保留。显式使用 P4 在线监督的示例（必须先复制源码和输入到独立运行副本）：

```bash
python -B train_sac.py --risk_variant m1 --risk_supervision horizon \
  --risk_dataset_dir /新的绝对路径/p4-train-data \
  --epochs 1 --max_e_steps 100 --save_interval 100 --dvc cuda --seed 100
```

新目录必须不存在。在线数据只有 train 身份，风险网络随训练变化，不能混入独立校准数据。验证/测试采集使用 `scripts/collect_p4.py` 的冻结模式，不调用 SAC 或风险器优化器。

## 隔离方案与审计产物

从原始交通文件按**完整路线边序列**的 SHA-256 分组，将所有同路线的 flow/vehicle 放入同一个集合，不能把同车相邻窗口随机切分。`topstraight`、`topleft`、`rightleft` 三条可控流分别固定为 train/validation/test 的锚点，其余路线按稳定哈希分配。保留所属子集的原始出发时间与流量，不通过改动作、标签、碰撞行为或提高流量凑正例。

三个集合的交通需求场景、完整路线和车辆 ID 必须隔离；道路基础设施仍共用原路网，**不是地理路网外推实验**。种子分别使用 100–149、200–249、300–349。不同集合背景流量组成和密度会变化，这是显式的需求场景泛化范围，不可把结果直接等同原完整交通流下的校准。

每份数据保存 `manifest.json`、`events.jsonl`、`samples.jsonl`、`counts.json` 和 `collection.json`。窗口包含原始张量、掩码、实际动作命令、决策步、路线哈希、车辆、上下文、分数、标签、终止原因及观察终点。审计器从原始事件重算标签，检查未执行样本、时间缺口、重复窗口、未关闭数据及跨集合泄漏。重复的确定性 seed/场景/检查点组合也拒绝，防止更换目录名后重复计数。

输出审计包括正负与删失窗口、车辆数、实际碰撞车辆事件数、动作分位数/直方图、AP 口径 AUPRC、AUROC、漏报及正例分母、Brier、ECE、可靠性箱和 SVG 图。单一类别时不可定义的指标输出 null，不伪造 0 或 1。原始样本保持自然事件比例；只有在线训练缓冲区使用平衡抽样。

每个风险器的 train/validation/test 使用相同冻结 actor/risk 检查点；校准只读 validation 标签。初始工程采集复用已验收的 P3 短运行权重，**它们没有自然风险训练更新，不是研究效果模型**。校准器只生成离线诊断产物，不自动替换在线奖励，更不宣布 P5 方法收益。

## 用户在服务器执行

推荐使用本轮提供的增量源码包，核对校验后在原项目根目录解压。它不含 references、旧模型或旧实验目录，也不会删除已有证据。必须保留服务器既有 `plan/p3/runs/20261121T092656852782Z/` 中的 actor 与 risk 权重；入口会检查这些文件。

```bash
cd ~/Work/LXM/SAC-STGR
conda activate SAC_RWB
sha256sum -c p4-implementation-20261121.tar.gz.sha256
tar -xzf p4-implementation-20261121.tar.gz
python -B scripts/accept_p4.py --steps 1000 --replicates 1
```

若不用增量包，需同步当前源码、scripts、tests、本文件、protocol.json、新阶段文档，以及 `plan/review/p0123-target-confirmation-20261121.json`。请不要覆盖服务器环境或旧实验结果。

入口先检查锁定环境与协议，执行全部回归和静态检查；然后 B0/M1 各做 100 步 P4 在线监督工程短运行；再各自以固定 P3 权重在三个隔离场景采集 1,000 次决策，审计并校准。各子进程有超时，所有运行写入新的 `plan/p4/runs/<UTC时间>/`，不会从旧权重续训或开始 P5。

| 结果 | 含义 |
|---|---|
| 退出码 0，target/passed=true | 目标工程验证及当前协议的自然事件最低支持门槛均通过，可审阅 P4 验收 |
| 退出码 2，engineering_passed=true，status=needs_more_natural_events | 标签/隔离链路可运行，但自然验证或测试事件不足；P4 尚不能完整验收 |
| 退出码 1，error 非空 | 环境、执行、数据完整性或隔离检查失败；保留目录定位 |

完整验收要求 train 至少有 64 个自然正例窗口与 64 个负例窗口（满足现有训练批次的双池最小支持）；验证、测试集分别至少有 **20 个自然正例窗口、20 个负例窗口及 5 辆不同的正例车辆**。这是预先固定的诊断支持门槛，不代表独立样本量或统计功效已经充分。相邻窗口相关，不能把窗口数称作独立碰撞事件数。

若返回 2，先回传原目录供复核；需要扩展自然采集时，再使用独立新运行，例如 `python -B scripts/accept_p4.py --steps 3000 --replicates 3`。不要改标签、制造碰撞、重采样独立评价集或降低门槛。重复运行同一 seed 的旧目录不可合并充数。

运行结束后回传整个新目录，至少需要 summary、environment、source-manifest、unit-results、static、protocol、scenarios，以及两组在线训练数据、冻结采集数据、audit、reliability 和各日志/退出码。当前代码的正式目标验收须以这些新证据为准。
